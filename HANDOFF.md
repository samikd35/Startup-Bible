## Decisions from the discussion

- **Personal use first, with a path to public GitHub release.** Keep one shared Markdown workflow for Codex, Cursor, and Claude Code. Use a project entry point where the client needs one.
- **Discover skills by capability.** Describe what a step needs and what it should produce. Check the skills available in the session and the team's approved library. Search the web for a material gap when the host provides search. Check fit, source, compatibility, and tool access. Use catalog installs as a tiebreaker. [Skills.sh methodology](https://www.skills.sh/docs)
- **Make pasted notes enough for the core workflow.** Use connected sources and destinations when available and requested. Guide the user through the client's install or sign-in flow when a missing tool matters, then verify access.
- **Keep a project record.** With logging enabled, record the trigger, handbook revision, evidence and output links, feedback, and known outcome in `startup/runs.md`. Record accepted choices and why they were made in `startup/decisions.md`. Keep source material in its existing location.

## Design questions to revisit

1. **How does customer context become a product recommendation?** Davidson describes combining meeting transcripts, user feedback, internal records, and documented decisions. Start with the pilot example and decide when a conversation is enough to suggest what to build, when to corroborate it, and who decides. Include relevant public discussions, such as Hacker News, as potential sources of hypotheses. Decide what evidence and reasoning the recommendation should preserve. [Davidson's account](https://www.linkedin.com/pulse/openai-acquires-odessia-francis-davidson-yolcc)
2. **When should background guidance appear?** Keep direct invocation available and design an opt-in project checkpoint with a visible trigger and pause control. Start from advice that shows its evidence and proposed next step. Ask a question when the answer would change the next action. Apply a change in strategy or scope when the user agrees. Choose the first checkpoint and where the suggestion should surface. [Codex hooks](https://learn.chatgpt.com/docs/hooks) · [Cursor hooks](https://cursor.com/docs/hooks) · [Claude Code hooks](https://code.claude.com/docs/en/hooks)
3. **How should the handbook improve?** Use recurring corrections, outcomes, and targeted public research to propose changes. Test the current and proposed instructions against the same examples, including a case where guidance should stay quiet. Have a maintainer review the change before publishing a new version. Decide the review cadence and owner. [Scheduled tasks](https://learn.chatgpt.com/docs/automations) · [Testing skills with evals](https://developers.openai.com/blog/eval-skills)

## Research notes on startup agent workflows

Sources reviewed November 12, 2026. The founder accounts describe how the companies worked and what their teams say they observed. Use the starting conditions and the specific workflow when deciding what to try in another venture.

### Early company cases

**Odessia.** Francis Davidson describes giving agents access to the relevant company sources, recording decisions in shared documentation, turning repeated corrections into skills, and using another model to critique results before human review. Concrete assignments included making a launch video and benchmarking partner APIs. His interview also describes a seven-person founding team with clear ownership and a product preview after about five months of development. The company brought travel-domain experience and investor backing to the experiment. [Acquisition and operating account](https://www.linkedin.com/pulse/openai-acquires-odessia-francis-davidson-yolcc) · [Founder interview](https://solofounders.com/blog/his-public-company-blew-up-he-came-back-solo)

**Customermates.** Bootstrapped founder Benjamin Wagner says Claude Code helped build much of the product and that he uses agents for the company's own sales and marketing. He approves what goes out. He attributes early users to communities, directories, and personal outreach tied to something a prospect actually posted. This account describes the first hosted teams after launch. [Founder Q&A](https://www.wearefounders.uk/customermates-founder-q-a-building-an-open-source-agent-operating-system/) · [Company account of its sales workflow](https://customermates.com/en/about)

**Polsia.** Solo founder Ben Cera describes using AI to build the business and running an internal support agent that handles credits and refunds and sends repeated issues toward engineering. In a separate interview he defined his reported run rate as the last 30 days annualized, including one-off payments, and estimated first-month churn at about 50% at that time. The support workflow is a case to study, and retention is an outcome to measure separately. [Founder interview on building](https://www.kevinrose.com/the-solopreneur-revolution-is-here/) · [Internal support interview](https://www.buzzsprout.com/2090897/episodes/19260431-how-he-built-a-250m-company-with-zero-employees-ben-cera-polsia) · [Founder interview on run rate and churn](https://mixergy.com/interviews/is-polsia-a-250m-scam-i-asked-the-founder-to-his-face/)

**Stella.** Sarah Perl describes using coding tools including Claude Code to prototype an iPhone app quickly and spending two to three months on the full product. For distribution, she filmed videos for her existing social audience and used ManyChat to send a download path in response to comments. This case pairs fast product prototyping with a distribution channel the founder already understood. [Founder interview and transcript](https://www.starterstory.com/stories/she-built-this-300k-month-app-in-60-days)

**Proaction.** Colin Knudsen, co-founder of a five-person fleet-software startup at the time of the OpenAI Academy profile, uses recordings, email, and spreadsheets to turn customer conversations into tailored demos with Codex. Those demos help engineers understand what to build when a prospect moves forward. He also uses Codex to prepare follow-ups, create Linear issues, update HubSpot opportunities, and prepare sales updates. The co-founder's reported 50–60% estimate concerns the increase in the share of deals moving into solution development. [Founder workflow](https://academy.openai.com/public/blogs/colin-knudsen-proaction-codex-customer-demos) · [Proaction case study](https://openai.com/index/proaction/)

### Practices from operating teams

- **Anthropic growth, legal, and finance.** Growth marketing used campaign-performance CSVs to generate ad variants under character limits and logged experiments for subsequent iterations. Legal prototyped routing to the right lawyer and tracking review status. Finance staff used written procedures to query company data and generate spreadsheets. These illustrate three tasks with defined inputs and outputs. [Anthropic's internal Claude Code report](https://www-cdn.anthropic.com/58284b19e702b49db9302d5b6f135ad8871e7658.pdf)
- **Clay, Exa, and Basis.** In OpenAI's operator cases, a Clay seller kept an evidence-linked account folder current and received suggested next steps. Exa moved from discovering integration opportunities to tested PRs, with people owning relationship decisions and commitments. Basis turned a demonstrated onboarding process into a skill that HR could improve as exceptions appeared. [OpenAI's operator cases](https://openai.com/index/ai-native-company-workflows/)
- **Lowtouch.ai.** Co-founder Rejith Krishnan describes account-specific context folders plus a common folder for sales and marketing material. An agent proposed CRM changes from Zoom notes for pre-sales staff to confirm, and the team used the same context for proposals and engineering requirements. [Co-founder's rollout account](https://www.lowtouch.ai/how-we-rolled-out-claude-code-across-an-entire-company/)
- **Intercom.** Its support team used capacity freed by Fin to trial more consultative help for self-serve accounts. The team tracked adoption, usage, and expansion among engaged accounts and accounts that did not respond. That comparison is observational and describes the combined support initiative. [Intercom support team account](https://www.intercom.com/blog/how-we-turned-support-into-a-revenue-engine-at-intercom)
- **Gilbert + Tobin.** The firm used Codex to help build a workflow that prepares reports for selected compliance checks, with people reviewing and signing off. The case shows how a defined review role fits into an operational workflow that uses sensitive sources. [Law firm case study](https://openai.com/index/gilbert-tobin/)

### Guides and standards for a reusable playbook

- **Early discovery and delivery.** Paul Graham describes founders manually recruiting early users and sometimes doing the work by hand. That provides a way to learn the process before writing an agent procedure. [Do Things that Don't Scale](https://paulgraham.com/ds.html)
- **Shared project instructions.** OpenAI's Codex engineering team found a short `AGENTS.md` useful as an index into maintained documentation. They gave agents ways to run the app and inspect tests, UI, and logs. [Harness engineering](https://openai.com/index/harness-engineering/)
- **Workflow design and tests.** Anthropic recommends starting with simple patterns and expanding complexity as the job needs it. Its evaluation guide starts from manual checks and real failures, with explicit inputs and pass criteria. [Building effective agents](https://www.anthropic.com/research/building-effective-agents) · [Demystifying agent evaluations](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)
- **Skill format and tool access.** The Agent Skills format uses a `SKILL.md` with a name and description, plus optional relative references, examples, and scripts. MCP provides a common protocol for reaching connected tools and data. The client and execution environment determine which tools and credentials are available. [Agent Skills specification](https://agentskills.io/specification) · [MCP introduction](https://modelcontextprotocol.io/docs/getting-started/intro)
- **Client discovery.** Codex and Cursor support repo-level `AGENTS.md` and `.agents/skills/`. Codex Cloud supports skills present in the repo. Claude Code can read `AGENTS.md` in supported configurations, and a project `CLAUDE.md` can explicitly import it. Claude's project skill directory is `.claude/skills/`. Its documentation describes separate account-enabled skills for Cowork and certain cloud sessions. [Codex instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md) · [Codex skills](https://learn.chatgpt.com/docs/build-skills) · [Codex Cloud](https://learn.chatgpt.com/docs/environments/cloud-environments#current-limitations) · [Cursor rules](https://cursor.com/docs/rules) · [Cursor skills](https://cursor.com/help/customization/skills) · [Claude project instructions](https://code.claude.com/docs/en/memory) · [Claude skills](https://code.claude.com/docs/en/skills)
